# 实时状态与额度读取的兼容性

2026-10-11 在 Codex Windows 26.1007.2314.0 发现：日志和对话费用仍可读取，但实时状态为空，账号额度无法取得。只读检查确认 React hook 中保存的是 host manager 数组；大量其他 hook 状态先填满了旧对象搜索队列，数组中的 manager 未在预算内被检查。

改为在收集 hook/context 值时先去重并立即检查小型数组、Map、Set 中的候选。找到本地 manager 即停止；保留原有遍历时间和数量上限，不扩大每次扫描对客户端的占用。排除已释放和远端 host manager。切换到尚未加载的对话时保留仍有效的账号读取入口，实时对话仍返回未知，直至该对话已有缓存。

读取范围继续限于客户端已有状态及两个只读方法 `account/rateLimits/read`、`account/read(refreshToken=false)`。不加载或恢复对话，不启动任务，不改变登录、额度、代理或客户端设置。

额度读取的两项请求并行进行，单项时限 8 秒、外层 10 秒，避免冷启动超过原来 2.5 秒就失败。失败 15 秒后重试，正常读取仍为 60 秒，手动刷新立即排队。后台用量重算期间只显示此前完整配对的百分比和金额，不把新百分比套在旧用量上；账号、周期改变或数据过期时不沿用旧配对。

测试覆盖大型 hook 队列、小型 manager 数组、本地/远端及已释放对象、对话加载空窗、并行只读参数、失败重试、手动刷新、账号隔离与配对采样。真实运行结果保存在本机忽略的 artifacts 目录，不提交用户会话或账号数据。

## 26.1021 客户端的已绑定状态容器

2026-10-24 排查发现客户端连接仍正常、源日志可读，但实时状态和账号额度同时不可用。26.1021.3705.0 把本地 host manager 保存在已绑定的 signal-family 中，普通对象遍历无法取得当前值。

v0.5.1 在已有 React scope 中识别缓存节点，仅读取 `local` 成员的已存在可写 signal atom。直接通过已有 store.get 取得当前值，不调用 family.resolve、signal.get、订阅或写入方法；不调用 query family，也不创建/恢复任务。只接受本地、未释放且提供账号请求方法的 manager，发现仍受原时间预算和最多 32 次 signal 读取约束。取得后沿用现有缓存，不在每次采样重新扫描。

额度请求缺少实时入口时单独返回 `runtime_unavailable`；不将其显示为非订阅账号或泛化的额度接口错误。实际账号接口继续使用只读请求、不刷新登录凭据。
